# state-management-principles

## Description

协助你应用SOLID、DRY、KISS和YAGNI原则设计优质React状态管理逻辑

## Content

使用本规则确保状态管理代码符合以下架构原则:

### 单一职责原则(SRP)
- 每个Hook只负责一个明确的功能领域
- 如useVectorsData只处理向量数据，不处理UI状态
- 当Hook变得复杂时，应进一步拆分为更小的Hook
- 保持每个Hook的职责清晰、边界明确

### 不重复原则(DRY)
- 避免重复的状态管理逻辑:
  - 将共享逻辑提取到通用Hook中
  - 使用组合方式复用现有Hook
  - 避免在不同组件中重复实现相似逻辑
- 创建可复用的抽象，但不过度抽象

### 简单原则(KISS)
- 保持状态管理逻辑简单明了:
  - 状态设计应该直观易懂
  - 避免过度设计和不必要的抽象
  - 使用清晰的命名和简洁的实现方式
- 优先使用标准React钩子，避免复杂解决方案

### 你不会需要它原则(YAGNI)
- 不实现当前不需要的状态和功能:
  - 只实现当前确实需要的状态
  - 避免为"将来可能"的功能创建复杂状态
  - 随需求变化逐步演进状态管理方案
- 消除未使用的状态和逻辑

### 状态隔离
- 实现状态的适当隔离:
  - 将UI状态与业务状态分离
  - 本地组件状态使用useState
  - 共享状态使用自定义Hook
  - 考虑状态的所有权和生命周期

### 安全最佳实践
- 遵循OWASP安全建议:
  - 敏感数据不应存储在持久状态中
  - 输入数据存入状态前进行验证
  - 避免在状态中存储未处理的用户输入
- 防止状态管理中的安全漏洞
